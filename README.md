# ai-delivery-acceptance

AI 交付验收标准方法论 · 配套工具与模板。

配套文章：[同一个 AI：我让它做出两套生产系统，也陪它聊了十轮人生——差别就在这四个字](https://blog.csdn.net/weixin_46582222/article/details/170984856)

## 核心观点

AI 的产出有没有价值，跟这件事有没有"对不对"有关系。验收标准不是给 AI 设的门槛，是给 AI 装的眼睛。

## 仓库内容

| 文件 | 用途 |
|---|---|
| `deploy_check.py` | 部署前验收检查脚本（可直接跑，可扩展）。每条检查输出 `[PASS]/[FAIL]` + 期望/实际，任何一条不过退出码 1 |
| `cards/任务前置卡.md` | 动手前填：目标、≥3 条可执行验收条件、失败长什么样、回滚方式。填不满就别开工 |
| `cards/部署前检查清单.md` | 部署前八条检查，覆盖"本地好好的、上线就出事"的绝大多数情况 |

## 快速开始

```bash
# 检查一个代码目录的语法与硬编码凭据
python deploy_check.py ./your_app

# 附加端口监听检查
python deploy_check.py ./your_app --port 8000
```

在 `CHECKS` 里追加你自己的验收条件——每条必须能变成一条命令、一个 URL、一句 SQL、一次点击。

## 三条提醒

1. 先写验收条件，再让 AI 写代码。顺序反了，后面全是返工。
2. 验收标准本身也会错、也会不全。每踩一个新坑，就往里补一条新条件。
3. 丢人的不是"推断"，是把"推断"讲成"已验"。
